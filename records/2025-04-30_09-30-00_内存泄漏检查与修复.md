## 2. 发现的问题

### 2.1 显存释放问题（严重）

| 项目 | 问题描述 | 严重程度 |
|-----|---------|---------|
| GPT-SoVITS | 推理完成后未调用 `torch.cuda.empty_cache()` | 高 |
| F5-TTS | 推理完成后未释放显存 | 高 |
| OpenVoice | 推理完成后未释放显存 | 高 |
| CosyVoice | 推理完成后未释放显存 | 高 |
| VoxCPM | 推理完成后未释放显存 | 高 |
| IndexTTS | 推理完成后未释放显存 | 高 |
| FireRedTTS2 | 推理完成后未释放显存 | 高 |
| Qwen3-TTS | 推理完成后未释放显存 | 高 |
| ChatTTS | 虽有显存释放，但不够完善 | 中 |

### 2.2 Python 垃圾回收问题（中等）

- 没有调用 `gc.collect()` 强制进行垃圾回收
- PyTorch 张量未显式删除（使用 `del`）

### 2.3 模型缓存问题（中等）

- 所有模型都被无限期缓存在内存中
- 没有模型卸载机制
- 服务运行时间越长，内存占用越大

### 2.4 临时文件清理（良好）

- 大部分路由正确地清理了临时文件（好的实践）

## 3. 修复方案

### 3.1 创建内存管理工具模块

**文件**: `backend/core/memory_utils.py`

新增以下功能：

1. `cleanup_memory()` - 清理内存和显存资源
2. `get_gpu_memory_info()` - 获取GPU内存使用信息
3. `log_gpu_memory_usage()` - 记录GPU内存使用情况
4. `release_tensor()` - 安全释放PyTorch张量
5. `GPUMemoryTracker` - GPU内存使用追踪器（上下文管理器）
6. `with_memory_cleanup` - 自动清理内存的装饰器
7. `clear_model_cache()` - 清理模型缓存

### 3.2 更新所有TTS路由

在每个TTS路由的推理完成后添加显存释放逻辑：

```python
# 清理显存 - 防止内存泄漏
if torch.cuda.is_available():
    del [相关张量变量]
    cleanup_memory()
    log_gpu_memory_usage("[项目名称]")
```

**修改的文件**:
- `backend/routers/tts/gptsovits.py`
- `backend/routers/tts/f5tts.py`
- `backend/routers/tts/openvoice.py`
- `backend/routers/tts/cosyvoice.py`
- `backend/routers/tts/voxcpm.py`
- `backend/routers/tts/indextts.py`
- `backend/routers/tts/fireredtts.py`
- `backend/routers/tts/qwen3tts.py`
- `backend/routers/tts/chattts.py`

### 3.3 新增系统管理API

**文件**: `backend/routers/system.py`

提供以下API端点：

| 端点 | 方法 | 功能描述 |
|-----|-----|---------|
| `/system/gpu-memory` | GET | 获取GPU内存使用情况 |
| `/system/models` | GET | 获取已加载的模型列表 |
| `/system/cleanup` | POST | 清理系统内存和显存 |
| `/system/clear-model/{model_key}` | POST | 清理指定的模型缓存 |
| `/system/clear-all-models` | POST | 清理所有模型缓存 |
| `/system/status` | GET | 获取系统状态概览 |

### 3.4 优化服务生命周期管理

**文件**: `backend/core/lifespan.py`

- 服务启动时记录更详细的显存信息
- 服务关闭时强制垃圾回收和显存清理
- 记录清理前后的显存变化

## 5. 使用说明

### 5.1 查看当前显存使用情况

```bash
curl http://localhost:8000/system/gpu-memory
```

### 5.2 查看已加载的模型

```bash
curl http://localhost:8000/system/models
```

### 5.3 手动清理内存和显存

```bash
curl -X POST http://localhost:8000/system/cleanup
```

### 5.4 清理指定模型（例如 ChatTTS）

```bash
curl -X POST http://localhost:8000/system/clear-model/chattts
```

### 5.5 清理所有模型

```bash
curl -X POST http://localhost:8000/system/clear-all-models
```

### 5.6 查看系统状态

```bash
curl http://localhost:8000/system/status
```

---

## 6. 建议

### 6.1 定期清理

建议在高频使用场景下，定期调用 `/system/cleanup` 接口清理显存。

### 6.2 模型切换策略

如果内存有限，可以在切换不同TTS模型前，先调用 `/system/clear-all-models` 清理已加载的模型。

### 6.3 监控告警

可以定期轮询 `/system/gpu-memory` 接口，当显存使用超过阈值时发出告警。
