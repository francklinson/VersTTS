# ChatTTS Web录音合成音频长度为0问题修复

**时间戳**: 2026-04-25 20:16:15  
**任务来源**: 需求.txt [1]使用web录制的人声作为参考,chattts合成的音频长度为0  
**修改文件**: backend/api_server.py

## 问题描述

使用web录制的人声(webm格式)作为参考时，ChatTTS合成的音频长度为0。

## 根本原因分析

通过分析ChatTTS官方示例代码，发现以下关键问题：

1. **核心Bug**: 当使用 `spk_smp` (从参考音频提取的说话人特征)时，必须将 `spk_emb` 设置为 `None`。同时传入两者会导致冲突，导致合成失败。

   参考代码来源: `algorithms/ChatTTS/examples/web/funcs.py` 第207-210行
   ```python
   if sample_text_input and sample_audio_code_input:
       params_infer_code.txt_smp = sample_text_input
       params_infer_code.spk_smp = sample_audio_code_input
       params_infer_code.spk_emb = None  # 关键: 使用spk_smp时必须设为None
   ```

2. **缺乏日志**: 原有的代码缺乏详细的日志记录，难以定位问题。

3. **缺少结果检查**: 没有检查合成结果是否为空，导致空音频被保存。

## 修复内容

### 1. 修复 spk_emb/spk_smp 冲突问题

在 `/tts/chattts` 接口中，当使用 `speaker_id` 加载已保存的说话人时：
- 提取 `spk_smp` 后，显式将 `spk_emb = None`
- 确保不会同时传入两个参数

```python
# 使用 sample_audio_speaker 提取 spk_smp 格式的 embedding
spk_smp = chat.sample_audio_speaker(wav_numpy)
txt_smp = "参考音频文本"  # 使用固定参考文本

# 重要: 使用 spk_smp 时必须将 spk_emb 设为 None
spk_emb = None
```

### 2. 添加详细日志

在说话人加载和音频合成过程中添加了详细的日志：

- 音频文件路径和格式信息
- ffmpeg转换过程和结果
- 音频加载后的形状、采样率、振幅范围
- 推理参数详情 (spk_emb/spk_smp/txt_smp状态)
- 合成结果检查 (长度、振幅)

### 3. 添加合成结果检查

在保存音频前增加了多项检查：
- 检查返回结果是否为空列表
- 检查音频数据是否为None
- 检查音频长度是否为0
- 检查音频是否几乎全为静音 (最大振幅 < 1e-5)

```python
# 检查合成结果
if not wavs or len(wavs) == 0:
    raise HTTPException(status_code=500, detail="语音合成失败: 返回结果为空")

if wavs[0] is None:
    raise HTTPException(status_code=500, detail="语音合成失败: 音频数据为None")

wav_length = len(wavs[0])
if wav_length == 0:
    raise HTTPException(status_code=500, detail="语音合成失败: 音频长度为0")

wav_max = np.abs(wavs[0]).max()
if wav_max < 1e-5:
    raise HTTPException(status_code=500, detail="语音合成失败: 音频几乎全为静音")
```
