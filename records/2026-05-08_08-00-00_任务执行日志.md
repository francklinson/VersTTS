## 二、transformers 版本冲突解决

### 2.1 问题描述
| 项目 | transformers 要求 | 原因 |
|------|-------------------|------|
| Qwen3-TTS | `==4.57.3` | 官方 pyproject.toml 明确要求 |
| OmniVoice | `>=5.3.0` | 使用了 5.x 新增的 API |

### 2.2 失败方案
1. ❌ 全局升级到 transformers 5.x：Qwen3-TTS/VoxCPM 全部崩溃
2. ❌ 运行时动态切换版本：PyTorch 模型对象保留了旧版本的内部状态

### 2.3 最终方案：独立服务架构
| 组件 | transformers 版本 | 运行方式 |
|------|------------------|---------|
| 主服务 (8000) | 4.57.3 | Qwen3-TTS/VoxCPM/OpenVoice 等 |
| OmniVoice (8001) | 5.6.2 | 独立进程，`lib/transformers5/` |

### 2.4 关键文件
- `lib/transformers5/` - 独立 transformers 5.6.2
- `omnivoice_service.py` - OmniVoice 独立服务
- `backend/routers/tts/omnivoice.py` - 通过 HTTP 调用独立服务
- `backend/engines/transformers_isolation.py` - transformers 兼容工具

## 五、服务器部署配置（消除硬编码）

### 5.1 集中配置于 start_server.sh
```bash
# 服务配置
HOST="0.0.0.0"
PORT="8000"

# OmniVoice 独立服务配置
OMNIVOICE_HOST="127.0.0.1"
OMNIVOICE_PORT="8001"

# 路径配置
MODELS_DIR="models"
OUTPUTS_DIR="outputs"
LOGS_DIR="logs"
SPEAKERS_DIR="speakers"

# 日志配置
LOG_LEVEL="INFO"
LOG_MAX_SIZE="50"
LOG_BACKUP_COUNT="5"

# 离线模式
TRANSFORMERS_OFFLINE="1"
HF_HUB_OFFLINE="1"
```

### 5.2 后端配置支持环境变量
- `backend/config.py` - 所有配置项支持环境变量覆盖
- `omnivoice_service.py` - MODEL_PATH 使用环境变量
- `backend/routers/tts/omnivoice.py` - 服务 URL 使用配置变量
