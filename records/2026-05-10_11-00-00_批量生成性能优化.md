## 一、问题分析

### 1.1 原始实现
原始批量生成使用简单的 `for` 循环**顺序执行**：
```python
for i in range(count):
    # 生成音频...
```
生成10个音频需要10倍时间。

### 1.2 显存风险
| 模型类型 | 显存占用 | 并行风险 |
|---------|---------|---------|
| VoxCPM | 4-8GB | **高** - 2个并行可能占用8-16GB |
| Qwen3-TTS | 4-6GB | **高** - 2个并行可能占用8-12GB |
| OmniVoice | 独立服务 | **低** - 独立进程，不会占用主服务显存 |

**结论**: 本地GPU模型不能并行，OmniVoice可以有限并行。

---

## 二、解决方案

### 2.1 并发策略
```python
# 并发控制配置
OMNIVOICE_CONCURRENCY = 2      # OmniVoice: 2并发
GPU_MODEL_CONCURRENCY = 1      # VoxCPM/Qwen3-TTS: 1并发（顺序执行）

# 信号量控制
omnivoice_semaphore = asyncio.Semaphore(OMNIVOICE_CONCURRENCY)
```

### 2.2 OmniVoice并行实现

使用 `aiohttp` 进行异步HTTP请求 + `asyncio.Semaphore` 控制并发：

```python
async def _generate_single_omnivoice(...):
    async with omnivoice_semaphore:  # 限制并发数
        # 异步HTTP请求
        async with session.post(...) as response:
            # 处理结果...

async def _batch_generate_omnivoice(...):
    # 创建所有任务
    tasks = [_generate_single_omnivoice(...) for i in range(count)]
    
    # 并行执行（受信号量控制实际并发数）
    results = await asyncio.gather(*tasks, return_exceptions=True)
```

### 2.3 安全措施

1. **超时控制**: 每个任务120秒超时，防止长时间阻塞
2. **异常隔离**: 单个任务失败不影响其他任务
3. **显存监控**: 新增 `/tts/batch/config` API 查询GPU状态
4. **保守并发**: OmniVoice仅2并发，本地模型保持顺序

## 四、性能对比

### 4.1 测试场景
- 生成10个音频
- OmniVoice随机音色模式

### 4.2 性能结果
| 实现方式 | 预计时间 | 提升 |
|---------|---------|------|
| 顺序执行 | ~300秒 | - |
| 2并发并行 | ~150-180秒 | **40-50%** |

### 4.3 显存影响
- **OmniVoice并行**: 不增加主服务显存占用（独立服务）
- **VoxCPM/Qwen3-TTS**: 保持顺序执行，显存占用稳定
