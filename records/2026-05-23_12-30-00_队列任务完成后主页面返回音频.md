# 任务队列完成后在主页面返回音频供试听

**时间**: 2026-05-23 12:30:00

## 问题描述

任务队列功能提交任务后，用户必须手动跳转到"任务队列"页面查看状态和下载音频。用户体验不佳，希望在各 TTS 模型主页面提交任务后，能够自动轮询任务状态并在完成后直接显示音频播放器和下载按钮。

## 修改内容

### 1. VoxCPM 页面修复

**文件**: `frontend/pages/voxcpm.html`

- 修复 `displayTaskResult` 函数中的 `audio_url` 拼接逻辑
- 原代码直接使用相对路径 `taskData.audio_url`，在某些部署环境下会导致 404
- 修复后自动判断是否需要拼接 `VersTTS.API_BASE` 前缀：
  ```javascript
  const audioUrl = taskData.audio_url.startsWith('http')
      ? taskData.audio_url
      : `${VersTTS.API_BASE}${taskData.audio_url}`;
  ```

### 2. Qwen3-TTS 页面添加轮询

**文件**: `frontend/pages/qwen3tts.html`

- 添加 `pollingTaskId` 和 `pollingInterval` 状态变量
- 重写 `addToQueue()` 函数：
  * 提交成功后不再清空输入框
  * 改为调用 `startPollingTask(data.task_id)` 启动轮询
- 新增 `startPollingTask(taskId)` 函数：
  * 显示结果区域为加载状态
  * 创建动态状态提示元素 `queueGenStatus`
  * 每3秒轮询 `/tasks/{taskId}/status`
  * 最多轮询300次（约15分钟）
- 新增 `stopPollingTask()` 函数：清理轮询定时器
- 新增 `displayTaskResult(taskData)` 函数：
  * 设置音频播放器 `src`
  * 设置下载链接 `href` 和 `download` 属性
  * 更新状态提示为"✅ 生成完成！"
  * 自动滚动到结果区域

### 3. OmniVoice 页面添加轮询

**文件**: `frontend/pages/omnivoice.html`

- 与 Qwen3-TTS 相同的轮询逻辑
- 适配 OmniVoice 特有的 DOM 元素 ID
- 下载文件名格式: `omnivoice_{task_id}.wav`

### 4. CosyVoice 页面添加轮询

**文件**: `frontend/pages/cosyvoice.html`

- 与 Qwen3-TTS 相同的轮询逻辑
- 适配 CosyVoice 特有的 DOM 元素 ID
- 下载文件名格式: `cosyvoice_{task_id}.wav`

## 统一交互流程

四个页面的任务队列交互现在完全一致：

1. **提交任务**: 用户点击"生成语音"，任务提交到队列
2. **显示等待状态**: 立即显示结果区域，展示蓝色提示"⏳ 任务已提交到队列，正在等待执行..."
3. **执行中状态**: 轮询到 `processing` 状态时，提示变为"🔧 正在生成音频，请稍候..."
4. **完成状态**: 轮询到 `completed` 状态时：
   - 停止轮询
   - 加载音频到播放器并显示
   - 显示下载按钮
   - 提示变为绿色"✅ 生成完成！"
5. **失败状态**: 轮询到 `failed` 状态时：
   - 停止轮询
   - 提示变为红色"❌ 生成失败: {错误信息}"
6. **超时状态**: 轮询超过300次（15分钟）后：
   - 停止轮询
   - 提示变为橙色"⏱️ 任务超时，请到任务队列页面查看结果"
