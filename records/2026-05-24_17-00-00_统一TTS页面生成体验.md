# 统一所有 TTS 页面的单音频/批量生成体验

**时间**: 2026-05-24 17:00:00
**任务**: 以 CosyVoice 为参考标准，统一所有 TTS 页面的单音频和批量生成交互体验

## 问题描述

用户反馈各 TTS 页面生成体验不一致：
1. **单音频生成**：CosyVoice 点击后立即显示状态提示（"⏳ 任务已提交..." / "🔧 正在生成音频..."），但 VoxCPM 缺少即时状态反馈
2. **批量生成**：CosyVoice 提交后提示"请前往任务列表查看进度"且按钮可用；Qwen3-TTS 批量生成后会页面内轮询，给人一种"仍在生成中"的感觉，按钮虽恢复但体验不一致

## 修改内容

### 1. Qwen3-TTS (`frontend/pages/qwen3tts.html`)
- **批量生成**：改回静态提示模式，与 CosyVoice 一致
  - 提交成功后显示进度条 100%，2 秒后自动隐藏
  - 提示：`已提交 X 个生成任务到队列，请前往任务列表查看进度`
  - **移除**页面内 `startPollingTask` 轮询批量结果（避免体验不一致）
- 保留单音频任务队列轮询逻辑不变

### 2. VoxCPM (`frontend/pages/voxcpm.html`)
- **`startPollingTask`**：完全重写为 CosyVoice 标准模式
  - 提交后立即创建/显示 `queueGenStatus` 元素
  - 初始状态：`⏳ 任务已提交到队列，正在等待执行...`
  - 执行中状态：`🔧 正在生成音频，请稍候...`
  - 超时提示：`⏱️ 任务超时，请到任务队列页面查看结果`
  - 自动滚动到结果区域
- **`displayTaskResult`**：完善结果展示
  - 添加 `audioPlayer` / `downloadLink` 的 `display` 控制
  - 添加 `statusEl` 更新为 `✅ 生成完成！`
- **`addToQueue`**：修复参数收集 bug
  - 说话人选择器 id 从错误的 `speakerSelect` 改为 `speakerSelectClone` / `speakerSelectUltimate`
  - 控制指令 id 从错误的 `controlPrompt` 改为 `cloneControlPrompt`

### 3. 后端 (`backend/task_handlers.py`)
- **`handle_qwen3tts_task`**：修复 custom_voice 模式下 speaker 参数读取
  - 原逻辑：`params.get('speaker', 'vivian')` — 批量生成时 `speaker` 为空，始终回退到 vivian
  - 新逻辑：`params.get('speaker') or params.get('speaker_id') or 'vivian'` — 支持批量任务中的 `speaker_id` 参数回退

## 体验统一后的行为

| 操作 | 所有页面统一行为 |
|------|-----------------|
| 点击"生成语音" | 立即显示结果区域 + 蓝色状态提示，3 秒轮询，完成后显示音频播放器 |
| 点击"批量生成" | 进度条走到 100%，2 秒后隐藏，提示"已提交到队列，请前往任务列表查看进度"，按钮恢复可用 |

## 测试验证

- CosyVoice: 已是标准，无需修改
- OmniVoice: 已符合标准，无需修改
- Qwen3-TTS: 批量生成改为静态提示 ✅
- VoxCPM: 单音频即时状态提示已添加 ✅
