## 二、PilotTTS 集成

### 基本信息
- **仓库**: https://github.com/AMAPVOICE/PilotTTS
- **路径**: `algorithms/PilotTTS/`
- **模型大小**: ~6GB
- **核心技术**: Qwen3-0.6B LLM + CosyVoice3 + w2v-bert-2.0

### 支持功能
| 模式 | 功能描述 | 模型 |
|------|---------|------|
| `voice_clone` | 零样本声音克隆 | pilot_tts.pt (base) |
| `emotion` | 11种情感合成 | pilot_tts_instruct.pt (instruct) |
| `dialect` | 14种中文方言合成 | pilot_tts_instruct.pt |
| `paralanguage` | 副语言合成 (笑/哭/咳嗽/呼吸) | pilot_tts_instruct.pt |

### 文件结构
| 文件 | 说明 |
|------|------|
| `algorithms/PilotTTS/` | 算法源代码和模型 |
| `backend/engines/pilottts_engine.py` | 模型加载引擎 |
| `backend/routers/tts/pilottts.py` | API 路由 (POST /tts/pilottts) |
| `frontend/pages/pilottts.html` | 前端页面 |
| `scripts/test_pilottts.py` | 测试脚本 |

### 修复的问题

#### 问题1: ONNX Runtime CUDA Provider 初始化失败
- **现象**: `CUDA failure 999: unknown error ; GPU=-1` 在 CosyVoice vocoder 加载时
- **根因**: ONNX Runtime 的 CUDAExecutionProvider 调用 `cudaSetDevice(-1)` 失败，破坏 CUDA 上下文，导致后续 PyTorch CUDA 操作也失败
- **修复**: 修改 `frontend.py` 第57行，`speech_tokenizer_session` 强制使用 `CPUExecutionProvider`
- **影响**: speech_tokenizer 是小型编码器，CPU 运行完全不影响性能

#### 问题2: CUDA_VISIBLE_DEVICES 空字符串
- **现象**: `cuInit` 返回 100 (CUDA_ERROR_NO_DEVICE)，0 GPU 可见
- **根因**: 环境中 CUDA_VISIBLE_DEVICES 被设置为空字符串 `""`
- **修复**: engine 加载时检测并删除空字符串变量
- **正确用法**: 不设置 = 所有 GPU 可见; 设置为 "0" = 第一个 GPU

#### 问题3: Tokenizer 路径解析
- **现象**: `AutoTokenizer.from_pretrained("tokenizer")` 失败: "not a local folder"
- **根因**: tokenizer 路径为相对路径，需解析为绝对路径
- **修复**: engine 加载时自动将相对路径转换为绝对路径

#### 问题4: Base/Instruct 模型 OOM
- **现象**: 加载 instruct 模型时 OOM (显存 24GB → 满)
- **根因**: 两个模型同时驻留显存 (base ~9GB + instruct ~9GB + 预加载 Qwen3-TTS ~8GB)
- **修复**: 自动互斥加载，切换类型时自动释放旧模型 (`cleanup_pilottts_engine`)

## 四、遗留问题

1. **方言模型未完全开放**: PilotTTS 演示代码中方言部分被注释，当前方言效果可能与期望有差距
2. **GPU 显存紧张**: 24GB RTX 3090 同时运行多个预加载模型 + PilotTTS 时显存紧张
3. **Qwen3-TTS 预加载占用**: ~8GB 显存，影响其他模型加载

## 五、部署建议

- 启动时避免预加载过多模型: 修改 `config.py` 中的 `PRELOAD_MODELS` 列表
- PilotTTS base/instruct 自动互斥，无需手动管理
- 确保 `CUDA_VISIBLE_DEVICES` 正确设置（非空字符串）
